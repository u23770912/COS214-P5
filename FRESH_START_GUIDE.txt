WHY THIS IS BETTER:
-------------------

BEFORE (The Problem):
- GUI ran separate C++ instance (option 3)
- Terminal ran separate C++ instance (option 2)
- Each had its own 8 hardcoded plants
- Changes in one didn't affect the other
- GUI showed stale data

AFTER (The Solution):
- Both use the SAME InventoryManager (singleton)
- Start with 0 plants, 0 workers
- Add everything dynamically via GUI
- All changes go through shared InventoryManager
- GUI shows real-time data


TECHNICAL DETAILS:
------------------

Changes Made:
1. createStaffContext() - Now creates empty staff system
2. runGreenhouseSimulation() - Starts with empty vectors
3. Command mode (option 3) - Starts with empty state
4. ADD_PLANT - Creates real PlantProduct objects
5. ADD_WORKER - Creates real Gardener/Cashier objects
6. GET_WORKERS - Returns actual staff roster
7. GET_PLANTS - Returns actual InventoryManager contents


Architecture:
Terminal (option 2)              GUI (NetBeans)
      ↓                                ↓
      ↓                                ↓
      └──────→  InventoryManager  ←────┘
                  (Singleton)
                      ↓
              Shared Plant Data
              Shared Worker Data


IMPORTANT NOTES:
----------------

1. InventoryManager is a SINGLETON
   - Only one instance exists
   - Both terminal and GUI access the same one

2. Plants added via GUI:
   - Go into InventoryManager.addToGreenhouse()
   - Terminal simulation sees them immediately

3. Workers added via GUI:
   - Go into StaffContext.roster
   - Available for command handling

4. State changes:
   - Plant advances lifecycle → State changes in memory
   - GUI refreshes → Reads current state

5. If terminal is running:
   - It will automatically process new plants
   - Worker activities will show new workers
