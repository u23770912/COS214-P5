WHAT IS OPTION B?
-----------------
Option B is the RECOMMENDED approach that runs a single unified C++ process with:
  ✓ Real-time terminal visualization of plant lifecycle
  ✓ Network server listening on port 8765 for GUI commands
  ✓ Instant synchronization - changes visible in both terminal and GUI
  ✓ Single source of truth - one InventoryManager, one state

This is better than Option A because:
  - No separate processes
  - True real-time updates
  - GUI sees exact terminal state
  - Terminal sees GUI changes immediately


HOW IT WORKS:
-------------

                Terminal Display              Network Socket (port 8765)
                     ↓                                 ↓
                     ↓                                 ↓
              ┌──────────────────────────────────────────────┐
              │   INTEGRATED C++ PROCESS (Option B)          │
              │                                              │
              │   • Lifecycle simulation thread              │
              │   • Network server thread                    │
              │   • Shared InventoryManager                  │
              │   • Shared StaffContext                      │
              └──────────────────────────────────────────────┘
                     ↓                                 ↓
               Updates every 1s                GUI connects via TCP
               Plant states advance            Sends commands
               Workers process                 Gets instant responses

TROUBLESHOOTING:
----------------

PROBLEM: "Failed to start network server"
SOLUTION:
  - Port 8765 may be in use
  - Try killing other processes: pkill greenhouse
  - Check if port is free: netstat -an | grep 8765

PROBLEM: GUI can't connect
SOLUTION:
  - Make sure terminal is running first
  - Check terminal shows "Waiting for connection"
  - Verify GUI is connecting to localhost:8765
  - Check firewall settings

PROBLEM: Plants not appearing in terminal
SOLUTION:
  - Check terminal shows "CONNECTED"
  - Verify ADD_PLANT command sent successfully
  - Look for response "OK Plant_X created"
  - Click refresh in GUI after adding

PROBLEM: State not updating
SOLUTION:
  - Terminal updates every 1 second automatically
  - GUI needs manual refresh (click "Refresh" button)
  - Both read from same InventoryManager


TECHNICAL DETAILS:
------------------

Network Server:
  - Uses standard POSIX sockets (sys/socket.h)
  - Non-blocking reads during simulation loop
  - Accepts one client at a time
  - TCP protocol on port 8765
  - Simple text-based commands

Simulation Loop:
  1. Check for incoming GUI command (non-blocking)
  2. If command received, process it immediately
  3. Advance all plant lifecycles
  4. Process staff command queue
  5. Update terminal display
  6. Sleep 1 second
  7. Repeat

Thread Safety:
  - Single-threaded for simplicity
  - Commands processed between simulation ticks
  - No mutex needed (sequential execution)
